# Состояние реализации Shronchik 0.1

Дата: 08.11.2026. Основа требований — предоставленные документы v1.1 в `specification` и последующие уточнения пользователя. Пользователь подтвердил общую медиатеку с личными историей, рекомендациями, альбомами, настройками и голосами. Наличие пункта в спецификации не означает, что он реализован.

## Принятые решения первого среза

1. React/TypeScript/Vite и ASP.NET Core .NET 10. Приложение открывается в браузере; WebView2 и установщик отдельным этапом. Сервер привязан к `127.0.0.1`; внешний HTTPS-адрес явно задаётся через PublicOrigin с доверенным локальным прокси. См. `HOSTING.md`.
2. SQLCipher через Microsoft.Data.Sqlite.Core и SQLitePCLRaw.bundle_e_sqlcipher. Шифрующий движок проверяется при каждом открытии; обычный SQLite не допускается. Ключ каталога отделён от мастер-ключа через HKDF, соединения без pooling, temp_store=MEMORY. Перед распространением необходимы проверка актуальности native-библиотеки, лицензий и SBOM.
3. У каждого аккаунта Argon2id/AES-GCM wrapper общего мастер-ключа. AAD связывает wrapper с UUID библиотеки и логином. Манифест v1 читается совместимо и сохраняется как v2 при изменении аккаунтов. Пароль меняет обёртку, исходники не перешифровываются. Начальная инициализация допускается только в пустой папке; потерянный манифест не заменяется новым поверх существующей библиотеки.
4. SRM1 v1 документирован в `../src/Shronchik.Core/Crypto/FORMAT.md`. Блоки 1 МиБ, отдельные ключи объектов, аутентифицированный заголовок, проверка GCM до выдачи блока. Пропускная способность на 20 ТБ/миллионах записей не измерялась.
5. Raw-body upload вместо multipart исключает буферизацию открытого файла через IFormFile. Импорт проходит через зашифрованный staging, затем атомарное переименование и транзакцию каталога. Magic bytes проверяются; полная валидация контейнера/декодирования ожидает ffprobe. Прогресс UI сначала отражает передачу, затем ожидание завершения шифрования.
6. Сессионный мастер-ключ находится в RAM. Lock отменяет поколение запросов, очищает принадлежащий сессии буфер; временные копии очищаются при завершении запроса. SQLCipher и управляемая среда имеют собственные буферы: обещания полного стирания всех копий из RAM не даются.
7. Пагинация подписана HMAC и привязана к запросу и ревизии каталога. При конкурентном изменении ленты требуется обновление; долгоживущий snapshot/keyset для больших библиотек пока не реализован. Поиск `instr` и seeded shuffle пока выполняют работу по набору кандидатов, полноценные FTS/план масштабирования впереди.
8. Удаление логическое: исходник остаётся зашифрованным, теги/рейтинг/избранное сохраняются. Срок новых удалений задаёт Admin, по умолчанию 30 дней; фоновый purge ещё не включён.
9. Словарь v2 в `shared/tags.json` содержит только 11 тегов с английским `label` и четыре группы с названиями RU/EN. Файл копируется в сборку сервера и включён в UI. Названия тегов не зависят от языка интерфейса; прежние ID и русские/английские синонимы служат только для распознавания. При первом открытии каталога с новой версией словаря транзакция объединяет совпадающие метки под новыми ID и удаляет все остальные назначения и устаревшие записи тегов, включая корзину, сохраняя медиа, оценки, альбомы и настройки. Изменение тегов инвалидирует курсоры; повторный вход с той же версией не повторяет очистку. API возвращает только разрешённые ID и отклоняет произвольные метки при импорте.
10. Настройки расширены до схемы v2 с семью разделами, частичными PATCH, предпросмотром, сбросом и переназначением клавиш. Старые сохранённые значения дополняются новыми значениями по умолчанию. Поля будущих FFmpeg/GPU/backup-возможностей отключены, сервер запрещает менять их через UI API.
11. Видеолента использует настраиваемое смешивание рейтинговых и случайных кандидатов 70/30; рейтинг и близость тегов по последним 30 просмотрам User имеют веса 60/40. Порог 7000 — изменяемое стартовое значение. Похожие видео учитывают пересечение тегов, случайная часть не повторяет их. Сохранение настроек обновляет ревизию и открытый список.
12. Каталог v3 хранит владельца истории, событий просмотров и альбомов. Миграция v2 назначает прежние записи аккаунту User. Каждая операция над альбомом проверяет владельца; HMAC-курсоры привязаны к аккаунту, альбому и соответствующим ревизиям. Рекомендации используют только историю текущего аккаунта. Изменение активности одного пользователя не инвалидирует ленту другого.
13. В новой библиотеке создаётся только Admin. Удаление обычного аккаунта сначала сохраняет запрет входа, отменяет его сеансы и ждёт завершения запросов. Затем транзакция очищает личные историю, предпочтения, настройки, голоса и альбомы, пересчитывает средние оценки, обновляет ревизию каталога и удаляет парольную обёртку аккаунта. Общие файлы, чужие голоса и счётчики сохраняются. Незавершённое удаление повторяется при следующем входе Admin; повторное использование логина допускается после очистки. Admin удалить нельзя.
14. По аудиту 07.11.2026 ограничены тела JSON, очередь проверки паролей, сеансы и контексты просмотров; миниатюры загружаются шестью параллельными запросами с ограничением размера. Видеолента ранжирует компактные данные до чтения текстов страницы, настройки читаются из того же snapshot. Исправлены усреднение tag affinity и случайное заполнение недостающих похожих видео. Результаты, замеры и границы проверки — в [AUDIT_2026-11-07.md](AUDIT_2026-11-07.md), полный список недостающего — в [AUDIT_GAPS_2026-11-07.md](AUDIT_GAPS_2026-11-07.md).

15. В хранилище добавлены перенос и подключение целой библиотеки с выбором папки на сервере. «Открыть» вызывает системный Windows IFileDialog на отдельном STA-потоке; отмена запроса закрывает принадлежащий ему диалог. Локальный Admin управляет расположением; все API-запросы и потоки завершаются перед сменой путей. Перенос проверяет копию до сохранения нового расположения и передаёт фактический прогресс по текущему HTTP-запросу в NDJSON: копирование, проверка и завершение. Процент достигает 100 только после сохранения пути и очистки источника; прежние JSON-клиенты поддерживаются. Подключение проверяет манифест, пароль Admin и зашифрованный каталог до переключения и отзывает прежние сеансы. Файл расположения сохраняется отдельно от переносимых данных, оба лаунчера учитывают выбор после перезапуска. NAS и аварийное отключение питания требуют отдельных испытаний.

16. Каталог v4 хранит голоса в `user_ratings` с уникальным ключом аккаунт/медиа. В одной транзакции изменяется только голос текущего User и пересчитывается среднее в `media.rating`; оно используется в галерее, сортировках и рекомендациях. Ответы Media содержат `rating`, `userRating` и `ratingCount`. Admin не голосует ни через плеер, ни через импорт или прямой API. Старые оценки без автора перенесены в зашифрованный `legacy_ratings` без создания вымышленных голосов.
17. Личные настройки хранятся по ключу `user:<accountId>`; общие параметры хранилища доступны только Admin. Рекомендации читают настройки текущего аккаунта из snapshot; сохранение личных настроек инвалидирует только его курсоры. AFK меняется во всех сеансах этого аккаунта. Меню аккаунта содержит настройки рядом с выходом. Главная и категории переключаются с плавным скрытием/появлением; уменьшение движения убирает задержку. Загрузка осталась внутри категорий, сортировка и увеличение миниатюр при наведении убраны; футер входа занимает нижний край страницы.

18. Право `canUpload` хранится отдельно от роли и активности аккаунта в манифесте; отсутствие поля означает запрет. Admin управляет им через галочку при создании и изменении пользователя. Разрешённые пользователи добавляют файлы и фотоальбомы в общую медиатеку, без удаления файлов и исходников, изменения существующих обложек и управления аккаунтами. Сессия и heartbeat возвращают актуальное право; UI обновляет его при опросе и закрывает открытый импорт после отзыва. При импорте видео выдаётся ограниченное по времени одноразовое разрешение на первую обложку, связанное с конкретным видео и сеансом; оно не позволяет заменить существующую обложку.

## Ближайшая последовательность

1. Довести защитное ядро: recovery-файл, тест потери паролей и переустановки Windows, согласованный backup/restore, аутентификация/версионирование манифеста, ревизия native-зависимостей.
2. Сделать импорт устойчивым к аварийному завершению: журнал jobs, сверка orphan/staging, отмена/возобновление; ffprobe, зашифрованные thumbnails/posters/previews. Проверка свободного места до импорта уже добавлена.
3. Расширить каталог: редактирование метаданных, дерево категорий, FTS, устойчивые к изменениям большие выборки и испытания рекомендаций на большом объёме.
4. Подключить недоступные пока параметры обработки, автоматическую очистку корзины, перенос диска/NAS и тесты объёма/длительной сессии.
5. Подключение выбранного домашнего HTTPS-прокси, WebView2, упаковка и проверка чистой Windows 11. Cast/GitHub остаются отдельными этапами.

Это первый вертикальный срез, а не закрытие всех P0 требований. Встроенные smoke-тесты доказывают перечисленные сценарии на синтетических данных; они не заменяют аудит криптографического формата, испытания на аварийном выключении и измерения на реальной библиотеке.
