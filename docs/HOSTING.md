# Домашний доступ к Shronchik

Медиатека и файлы общие. История, рекомендации, альбомы, настройки и голоса принадлежат вошедшему аккаунту. Общая оценка — среднее голосов обычных пользователей; Admin не голосует. Настройки открываются в меню аккаунта рядом с выходом. Admin создаёт и удаляет аккаунты в «Настройки → Пользователи», отключает доступ и выдаёт временные пароли. После первого входа пользователь задаёт собственный пароль.

Admin входит только с самого компьютера с сервером через **http://127.0.0.1:5271** или **http://localhost:5271**. Этот локальный адрес доступен и во время HTTPS-хостинга. Через внешний HTTPS-адрес запрещены вход Admin, разблокировка и обращения с его локальной cookie. Для доступа извне используйте обычный аккаунт.

## Подготовка аккаунтов

Запустите приложение локально через `Start-Shronchik.cmd`. Существующие аккаунты сохраняются при обновлении. На новой библиотеке создаётся только Admin с паролем 1111.

Текущий пароль Admin можно сохранить: этот аккаунт доступен только локально. Для личных просмотров создайте обычный аккаунт. Прежний User при наличии можно удалить через «Пользователи». Сетевой режим запускается, когда у всех включённых обычных аккаунтов заданы пароли длиной от 12 символов. Начальный локальный пароль Admin не мешает HTTPS-запуску.

## HTTPS через локальный прокси

Сервер приложения слушает `127.0.0.1`. Для внешнего доступа TLS-прокси на том же компьютере передаёт запросы на `http://127.0.0.1:5271`. Shronchik принимает внешний адрес, явно заданный при запуске.

```powershell
./scripts/start.ps1 -PublicOrigin 'https://ваш-адрес'
```

Замените пример фактическим HTTPS-адресом без пути. Прокси должен передавать исходный Host или X-Forwarded-Host и X-Forwarded-Proto=https. Приложение доверяет одному прокси-переходу только с loopback и проверяет внешний адрес, Origin и CSRF. В этом режиме для HTTPS-сеансов выставляется Secure cookie. Такое ограничение доверенных прокси соответствует [документации ASP.NET Core](https://learn.microsoft.com/en-us/aspnet/core/host-and-deploy/proxy-load-balancer?view=aspnetcore-10.0).

## Закрытая сеть Tailscale

Если выбран Tailscale, установите его на сервере и устройствах друзей, настройте доступ к серверу в своей частной сети и используйте его HTTPS-имя как PublicOrigin. После настройки Tailscale Serve команда для локального приложения выглядит так.

```powershell
tailscale serve --bg http://127.0.0.1:5271
```

Права в сети Tailscale и аккаунты Shronchik настраиваются отдельно. Актуальные параметры описаны в [документации Serve](https://tailscale.com/docs/reference/tailscale-cli/serve) и [документации доступа к частному серверу](https://tailscale.com/docs/share).

## HTTPS по белому IPv4 без домена

Установлен Caddy 2.11.9 из официального архива Windows amd64. Контрольная сумма архива SHA256 проверена; скрипты дополнительно проверяют исполняемый файл. Для публичного IP явно выбран ACME issuer Let's Encrypt с профилем shortlived и default_sni. Сертификат автоматически продлевается работающим Caddy. [Профиль сертификатов Let's Encrypt](https://letsencrypt.org/2026/01/15/6day-and-ip-general-availability), [default_sni Caddy](https://caddyserver.com/docs/caddyfile/options#default-sni).

На роутере закрепите локальный IPv4 компьютера и направьте TCP 80 и 443 на такие же порты этого компьютера. Порт 5271 используется только внутри компьютера. Текущие обнаруженные адреса записаны в сгенерированном Caddyfile, который хранится в data/hosting и исключён из Git. Если провайдер изменит внешний IP, подготовьте конфигурацию заново.

Подготовка конфигурации не запускает серверы и не запрашивает сертификаты.

```powershell
./scripts/prepare-https.ps1 -PublicIP 'ВАШ_БЕЛЫЙ_IP'
./scripts/build-hosting.ps1
./scripts/open-https-firewall.ps1 -WhatIf
```

После проверки правил роутера и паролей разрешите входящие TCP 80 и 443 только программе Caddy командой ниже в PowerShell с правами администратора. Правило не открывает другие порты или программы.

```powershell
./scripts/open-https-firewall.ps1
```

Остановите обычный локальный экземпляр Shronchik, чтобы освободить библиотеку и порт 5271. HTTPS-запуск использует отдельную опубликованную Release-сборку и сохраняет сертификаты в data/hosting/certificates.

Если запуск сообщает `Busy ports`, рядом с каждым портом указаны имя процесса и PID. Закройте окно предыдущего локального или HTTPS-запуска и повторите запуск. Одна библиотека допускает только один экземпляр сервера, поэтому смена порта не позволяет одновременно открыть её в двух режимах.

Для обычного запуска дважды щёлкните **`Start-Shronchik-Host.bat`** в корне проекта. Батник использует внешний IPv4 и порт из ранее подготовленного `data/hosting/Caddyfile`. Пока окно открыто, сервер и Caddy работают. Закрытие окна или `Ctrl+C` завершает оба процесса; закрытие окна также завершает сервер при локальном запуске через `Start-Shronchik.cmd`. Процессы привязаны к Windows Job Object, поэтому они не остаются в фоне даже при аварийном завершении запускающего PowerShell.

При первой настройке или изменении IP укажите адрес явно. Обычный запуск автоматически пересобирает опубликованную HTTPS-версию при изменении исходников, словаря тегов или файлов сборки. Локальная и HTTPS-сборки проверяются отдельно: обновление локальной версии больше не оставляет друзей на старой версии. При отсутствии записи об успешной сборке она также пересобирается. `-Rebuild` принудительно пересобирает, `-NoBuild` явно запускает готовую версию без проверки актуальности.

```bat
Start-Shronchik-Host.bat -PublicIP ВАШ_БЕЛЫЙ_IP
Start-Shronchik-Host.bat -Rebuild
```

Тот же запуск из PowerShell:

```powershell
./scripts/start-https.ps1 -PublicIP 'ВАШ_БЕЛЫЙ_IP'
```

После успешного выпуска сертификата адрес имеет вид https://ВАШ_БЕЛЫЙ_IP. Обычные аккаунты с короткими паролями не допускаются в сетевой режим. Публичную доступность нужно проверять через другую сеть, например мобильный Интернет.

## Обновление и копия

Проверка обновления: `powershell.exe -NoProfile -ExecutionPolicy Bypass -File tests/build-freshness-smoke.ps1` проверяет обнаружение устаревших исходников и файлов сборки на синтетических данных. Для проверки именно опубликованной HTTPS-сборки после `./scripts/build-hosting.ps1` выполните:

```powershell
$env:SHRONCHIK_TEST_SERVER_ROOT = (Resolve-Path '.tools/hosting/server').Path
try { node tests/http-smoke.mjs } finally { Remove-Item Env:SHRONCHIK_TEST_SERVER_ROOT }
```

Этот тест создаёт отдельную синтетическую библиотеку в `.cache` и проверяет в том числе вход друга через доверенный прокси, ровно 11 актуальных тегов и выдачу опубликованных файлов интерфейса. Рабочая медиатека не используется.

Перед переходом к аккаунтам сохранена копия манифеста, зашифрованной базы и предыдущей сборки в `.cache/pre-users-*`. Исходные медиа продолжают храниться в `data/library/vault`. При миграции история прежней библиотеки переносится к аккаунту User. По запросу владельца старый User удалён из рабочей библиотеки вместе с личными данными; общие файлы и текущий пароль Admin сохранены. Перед удалением создана копия метаданных в `.cache/pre-delete-user-*`. Новые аккаунты начинают с пустыми личными данными.

Для полной резервной копии остановите сервер и скопируйте всю папку библиотеки, включая library.json, db и vault. Копии только базы и манифеста недостаточно для восстановления медиа.
