# Shronchik

Локальная медиатека для Windows по предоставленной спецификации v1.1. Реализован первый рабочий прототип 0.1: вход → импорт одного файла → зашифрованное хранение → галерея → просмотр → оценка и избранное → блокировка.

## Запуск

В этой рабочей папке уже загружены локальный .NET 10 SDK и зависимости интерфейса. Для локальной работы запустите **`Start-Shronchik.cmd`** и откройте **http://127.0.0.1:5271**. Для HTTPS-хоста запустите **`Start-Shronchik-Host.bat`**: он использует ранее подготовленный внешний IPv4 и порт. Пока окно открыто, хост работает. Закрытие окна или `Ctrl+C` останавливает сервер и запущенный им HTTPS-прокси.

На новой библиотеке доступен **Admin** с начальным паролем **`1111`**. Существующие пароли сохраняются. Настройки открываются из меню аккаунта рядом с «Выйти». Admin создаёт аккаунты, управляет доступом и удаляет пользователей в «Настройки → Пользователи». Галочка «Разрешить загрузку» отдельно разрешает выбранному пользователю добавлять файлы и фотоальбомы, без права удаления. У новых и существующих пользователей она по умолчанию выключена; изменение сохраняется сразу и применяется к открытым сеансам. Новый пользователь при первом входе меняет временный пароль. Свой пароль можно изменить в «Безопасность».

**Admin доступен только на самом компьютере с сервером через http://127.0.0.1:5271 или http://localhost:5271** (при другом порте замените `5271`). Это работает и во время HTTPS-хостинга. Через внешний адрес вход и использование сеанса Admin запрещены; обычные аккаунты могут входить через HTTPS.

Настройка доступа для друзей через HTTPS описана в [docs/HOSTING.md](docs/HOSTING.md).

Результаты оптимизации и проверки защиты: [аудит 07.11.2026](docs/AUDIT_2026-11-07.md), [проверки безопасности](docs/SECURITY_REVIEW.md), [сверка требований и список следующих работ](docs/AUDIT_GAPS_2026-11-07.md).

Отдельный `tests/xss-browser-smoke.cjs` проверяет сохранённый HTML-подобный ввод в настоящем Edge на новой синтетической библиотеке. Вместе с общей командой и восемью UI-регрессиями прошли 184 проверки/сценария; подробности и ограничения — в отчёте аудита.

```powershell
# Быстрый запуск уже собранной версии
./scripts/start.ps1 -NoBuild

# Обычный запуск автоматически пересобирает изменённые исходники
./scripts/start.ps1

# Принудительная пересборка
./scripts/start.ps1 -Rebuild

# Другой порт и отдельная библиотека
./scripts/start.ps1 -Port 5272 -LibraryPath 'D:\ShronchikLibrary'
```

На новом компьютере нужны Windows x64, Node.js 22.12+ и .NET 10 SDK. Вместо системной установки .NET можно выполнить `./scripts/setup.ps1`: официальный SDK загрузится в `.tools/dotnet`. Первый запуск без готовой сборки устанавливает npm/NuGet-зависимости через Интернет. Обычный локальный и HTTPS-запуск проверяют содержимое исходников, словаря тегов и готовой сборки: при изменениях автоматически пересобирают соответствующую версию, иначе используют готовую сборку. `-Rebuild` принудительно пересобирает, а `-NoBuild` явно пропускает проверку актуальности. Неизменённая сборка работает локально без обязательного Интернета. Проверено в текущей среде на Node.js 24.12 и .NET SDK 10.0.403.

## Что работает

- RU/EN, настраиваемые темы, три корневых раздела Фото / Видео / GIF, адаптивная сетка с виртуализацией и масштабом текста. Галерея использует ширину окна, на телефоне фильтры открываются выдвижной панелью.
- Аккаунты создаёт Admin, публичной регистрации нет. Admin работает только через прямой локальный адрес на компьютере с сервером; HTTPS-прокси не допускает его вход и использование локального сеанса. Argon2id, временные пароли с обязательной сменой, отключение аккаунта с отзывом сессий, удаление аккаунта вместе с личными данными при сохранении общей медиатеки, cookie HttpOnly/SameSite=Strict, Host/Origin/CSRF-проверки.
- Импорт PNG/JPEG/WebP/GIF/MP4/WebM, теги, проверка сигнатуры, потоковый SHA-256 и дедупликация. Добавление файлов доступно Admin и пользователям с разрешением «Разрешить загрузку» внутри категорий; «Загрузить альбом» в разделе Фото принимает несколько PNG/JPEG/WebP с общими тегами. На главной кнопок загрузки нет. Фотографии последовательно добавляются в общую медиатеку; доступны прогресс, остановка и повтор только незагруженных файлов. По умолчанию исходники остаются на месте. Admin в обоих окнах может включить «Удалять оригиналы после загрузки» и предоставить браузеру доступ на изменение папки с исходниками. После успешного сохранения зашифрованной копии (и выбранной обложки видео) исходник проверяется и удаляется без корзины. Изменённые файлы, дубликаты и неудачные или отменённые загрузки сохраняются; неудачное удаление можно повторить отдельно. Обрабатываются только выбранные файлы непосредственно в указанной папке, без обхода подпапок. Нужен браузер с File System Access API (Edge/Chrome) через localhost или HTTPS; доступ не запоминается приложением между окнами импорта.
- В «Фото» загружаются PNG, JPEG и WebP, в «Видео» — MP4, M4V, MOV и WebM. В «GIF» через «Добавить файл» можно выбрать готовый GIF или видео одного из этих форматов. При добавлении видео браузер автоматически преобразует его с помощью FFmpeg.wasm и передаёт в медиатеку готовый GIF. Конвертация использует исходное разрешение и всю длительность ролика. Задержки кадров округляются до сотых долей секунды, а кадры с интервалом меньше 20 мс могут пропускаться, чтобы сохранить скорость анимации. Сервер сверяет расширение и сигнатуру загруженного файла с разделом.
- Оригиналы в блочном AES-256-GCM-контейнере SRM1, метаданные в SQLCipher. Открытые медиа не записываются во временные файлы.
- Общий каталог, теги, рейтинг и избранное. История каждого аккаунта хранит до 10 последних объектов каждого типа; служебный Admin её не записывает. Старая история переносится к прежнему User.
- Личные альбомы с созданием, переименованием, удалением и добавлением файлов через плеер. Файлы в альбомах ссылаются на общую медиатеку.
- Встроенный словарь из 11 тегов в `shared/tags.json`: Asia, Black, White, Latina, European, Dark hair, Light hair, With makeup, Without makeup, With tattoos и Without tattoos. Теги всегда отображаются на английском; только группы «Раса», «Прическа», «Макияж» и «Тату» переключаются между русским и английским. Произвольные теги при импорте не допускаются. При первом открытии каталога со словарём v2 совпадающие старые метки переносятся на новые ID, остальные удаляются с медиа, включая корзину; сами файлы и прочие метаданные сохраняются.
- Личная видеолента: по умолчанию 70% рейтинговых и 30% случайных кандидатов, веса общего рейтинга и тегов 60/40 с историей последних 30 просмотров текущего аккаунта; похожие и случайные видео под плеером.
- Фото/GIF и встроенный видеоплеер с ручным запуском и HTTP Range. При наведении на шкалу виден кадр соответствующего момента, полноэкранный режим сохраняет элементы управления. Громкость и выключение звука запоминаются в браузере отдельно для каждого аккаунта, включая Admin. Изменение начальной громкости в настройках имеет приоритет. Воспроизведение ограничено поддержкой кодеков браузером.
- Миниатюры видео показывают длительность и метку `ultra short` (до 30 секунд), `short` (до 3 минут), `medium` (до 10 минут), `long` (менее 40 минут), `ultra long` (от 40 минут). Диапазон 25–40 минут относится к `long`. Наведение или фокус с клавиатуры запускает короткое беззвучное превью с настраиваемой задержкой; одновременно работает одно превью. Системное или явно включённое уменьшение движения отключает автопревью.
- Обложки видео в галерее, плеере и рекомендациях. Admin и пользователи с правом загрузки выбирают кадр или загружают своё изображение при импорте; менять уже сохранённую обложку через «Сменить обложку» может только Admin. Выбранные обложки шифруются. Для старых видео без обложки браузер извлекает кадр при показе карточки.
- Каждый User ставит одну личную оценку `1–10000`, меняет или удаляет свой голос. Общий рейтинг — среднее арифметическое всех голосов, округлённое до целого; при отсутствии голосов оценки нет. Плеер отдельно показывает среднее, число голосов и вашу оценку. Admin голосовать и задавать оценку при импорте не может. При обновлении каталога до v4 старые оценки без автора сохраняются в зашифрованной таблице `legacy_ratings` и не входят в среднее. Избранное доступно обеим ролям. Просмотры видео учитываются один раз за открытие страницы только у User.
- Ручная и серверная AFK-блокировка, отмена действующих потоков, возврат в просмотр на паузе. По умолчанию 5 минут; воспроизводимое видео приостанавливает отсчёт.
- Корзина с восстановлением метаданных и настраиваемым сроком для новых удалений. Проверка каталога и свободного места, резерв места при импорте.
- Настройки внешнего вида, галереи, воспроизведения, рекомендаций, горячих клавиш и AFK сохраняются отдельно для каждого аккаунта, включая Admin. Только параметры общего хранилища применяются ко всей медиатеке. Admin также видит «Пользователи». Доступны предпросмотр и сброс темы, 13 переназначаемых сочетаний с проверкой конфликтов и серверное разграничение прав.
- Переходы между главной и категориями плавно скрывают и показывают содержимое с учётом настройки уменьшения движения. Миниатюры не увеличиваются при наведении; кнопка сортировки убрана. Подпись «Shronchik by kentakle» есть на главной и у нижнего края экрана входа.
- В «Настройки → Хранилище» Admin может выбрать папку и перенести библиотеку целиком или подключить существующую. Папки выбираются на компьютере с сервером. Перенос сохраняет БД, файлы, аккаунты и настройки, проверяет копию перед переключением и запоминает путь для следующих запусков. Для подключения нужен пароль Admin выбранной библиотеки; после проверки требуется повторный вход.

## Данные и ограничения прототипа

По умолчанию библиотека находится в `data/library`, отдельно от приложения. `library.json` содержит ID и парольные обёртки ключа; каталог — `db/catalog.sqlite`, зашифрованные оригиналы — `vault`. Эти данные, `.cache`, `.tools` и зависимости исключены из Git. Не удаляйте библиотеку для обновления программы. Для переноса используйте «Настройки → Хранилище → Перенести БД» и выберите пустую или новую папку. «Подключить БД» открывает готовую библиотеку с её аккаунтами и настройками. Выбирайте корневую папку с `library.json`, `db` и `vault`. Смена библиотеки завершает все текущие сеансы. Для ручной резервной копии остановите сервер и копируйте библиотеку целиком вместе с манифестом; для доступа нужен действующий пароль.

Выбранное расположение сохраняется рядом с первоначальным путём в `data/library.location.json` (либо `<LibraryPath>.location.json` для отдельного пути запуска). Сервер читает его и при обычном, и при HTTPS-запуске. Если сохранённая библиотека недоступна, запуск завершится ошибкой без создания пустой библиотеки. `SHRONCHIK_STORAGE_CONFIG` позволяет задать отдельный файл расположения при прямом запуске сервера.

В окне переноса или подключения кнопка «Открыть» вызывает системный выбор папки Windows на компьютере с сервером. Путь также можно ввести вручную и перейти к нему внутри приложения. Во время переноса отображаются фактический процент, объём и этап работы: копирование, проверка и завершение. 100% появляется после сохранения нового расположения и завершения очистки исходной папки.

**Прототип ещё не готов для единственного экземпляра личного архива.** Recovery-файл, проверенные backup/restore и перенос на NAS ещё не реализованы. До их проверки используйте нейтральные тестовые материалы и сохраняйте исходники отдельно.

На следующем этапе: устойчивые задания импорта и проверка через ffprobe/FFmpeg, серверная подготовка превью, вложенные категории, FTS, recovery и резервные копии. Соответствующие параметры обработки в настройках отключены с пояснениями. Автоматическая окончательная очистка корзины ещё отсутствует. При сбое между публикацией файла и транзакцией возможен зашифрованный объект без записи каталога; сверка таких объектов пока не автоматизирована. Установщик, WebView2-оболочка, Cast и публикация GitHub не выполнены.

## Проверки и структура

Остановите запущенный сервер, затем выполните `./scripts/test.ps1`. Проверки используют синтетические данные в `.cache`, отдельный HTTP-сервер на порту 5279 и не обращаются к вашей основной библиотеке.

Отдельная проверка завершения хоста: `powershell.exe -NoProfile -ExecutionPolicy Bypass -File tests/host-lifecycle-smoke.ps1` (нужны готовая сборка и локальный Caddy). Она поднимает сервер и прокси на динамических loopback-портах, аварийно завершает запускающий процесс без `finally` и проверяет завершение обоих дочерних процессов, освобождение портов, вывод консоли и код завершения. Используются только синтетические данные; сертификаты не запрашиваются.

Новые возможности медиа проверяет `node tests/media-features-smoke.cjs` после сборки UI; `SHRONCHIK_PLAYWRIGHT` должен указывать на установленный пакет Playwright. Проверка использует только синтетические API и медиа: пакетную загрузку с общими тегами, остановку и повтор, границы длительности, превью карточек и шкалы, полноэкранный режим и сохранение громкости обеих ролей. Снимки интерфейса сохраняются в `.cache/media-features-smoke`.

Разрешение загрузки проверяет `node tests/upload-permissions-ui-smoke.cjs` с `SHRONCHIK_PLAYWRIGHT`: создание аккаунта с галочкой, одиночная и пакетная загрузка обычным пользователем, отсутствие удаления, отзыв права в открытом окне и повторное разрешение. Проверка поднимает отдельный сервер и новую синтетическую библиотеку; снимки — в `.cache/upload-permissions-ui-smoke`. HTTP-проверки также охватывают сохранение права после перезапуска, совместимость старых аккаунтов, загрузку через HTTPS и одноразовое разрешение первой обложки видео.

Удаление исходников проверяет `node tests/source-deletion-smoke.cjs` с тем же `SHRONCHIK_PLAYWRIGHT`: сверка содержимого и метаданных, большие файлы по блокам, отказ доступа, изменение исходника, отмена, одиночная и пакетная загрузка, повтор удаления без повторной загрузки. Проверки используют только файлы в памяти и синтетический API; пользовательские исходники не удаляются.

Изменения интерфейса и личных данных проверяет `node tests/interface-smoke.cjs` с тем же `SHRONCHIK_PLAYWRIGHT`: футер на телефоне и высоком экране, меню аккаунта, отдельные настройки после перезагрузки и смены аккаунта, анимация переходов и уменьшение движения, отсутствие сортировки и увеличения миниатюр, личный голос и средняя оценка, отсутствие голосования у Admin. Снимки — в `.cache/interface-smoke`. Серверные проверки включают одновременные голоса, обновление старого каталога, удаление голосов и настроек вместе с аккаунтом и запрет оценки через API Admin.

Проверки 07.11.2026: сборка без ошибок и предупреждений, 29 проверок криптографии, 82 каталога, 33 сессий/AFK, 24 сквозных HTTP и 9 сценариев защиты. HTTP-проверки включают запрет внешнего входа Admin, переноса локальной cookie и подмены proxy-заголовков при сохранении HTTPS-доступа обычных аккаунтов. Отдельные 8 браузерных регрессий (`tests/frontend-smoke.cjs`, нужен `SHRONCHIK_PLAYWRIGHT`) проверяют очередь миниатюр, гонки ответов, переходы и сброс фильтров. В Edge с настоящим сервером проверены создание/удаление аккаунта, отзыв открытого сеанса, первый вход и смена временного пароля, личные альбомы и история двух пользователей, импорт и обложки. Проверены сохранность общей медиатеки и чужих личных данных при удалении, повторное использование логина и восстановление прерванного удаления. Адаптивность проверена на ширинах 390–5120 пикселей. Benchmark на 100k синтетических метаданных ускорил видеоленту с 3273,5 до 738,3 мс; условия и ограничения приведены в отчёте аудита. WebView2, NAS, миллион записей и производительность большой реальной библиотеки ещё требуют испытаний.

```text
src/Shronchik.Core/       криптография SRM1 и парольные обёртки
src/Shronchik.Server/     ASP.NET Core, сессии, SQLCipher, импорт и потоки
src/Shronchik.Web/        React + TypeScript + Vite
tests/                   криптография, каталог, HTTP-сценарии
scripts/                 установка SDK, запуск, проверки
shared/tags.json          английские теги, группы RU/EN и прежние синонимы
docs/specification/      предоставленная исходная документация v1.1
docs/IMPLEMENTATION.md   решения и следующие этапы
```

При разработке UI: запустите сервер с `ASPNETCORE_ENVIRONMENT=Development`, затем `npm run dev` в `src/Shronchik.Web`. Vite использует `127.0.0.1:5173` и проксирует API на `127.0.0.1:5271`. Обычный запуск обслуживает собранный UI из локального сервера.
